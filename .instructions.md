# Local AI Agent — Development Instructions

This file provides templates and workflows for common tasks in the `LOCAL AI AGENT` repository.

## Task Templates

### 1. Code Refactor or Feature
**When:** Improving readability, adding logging, or implementing a small feature.

**Steps:**
1. Read the target file to understand current structure.
2. Plan the changes (extract functions, rename variables, add type hints).
3. Apply a patch with the refactored code.
4. (Optional) Create a simple test to verify behavior.

**Example prompt:**
> Refactor `aws_infrastructure.py` to add logging and improve error handling.

---

### 2. Add Unit Tests
**When:** Creating or updating tests for a module.

**Steps:**
1. Review the module's public API.
2. Design test cases (happy path, edge cases, errors).
3. Create a `test_<module>.py` file or patch an existing one.
4. Run tests locally to verify coverage.

**Example prompt:**
> Add unit tests for `vector.py` covering normalization and distance computation.

---

### 3. Docker / Infra Changes
**When:** Updating `Dockerfile`, deployment scripts, or cloud configs.

**Steps:**
1. Review the current file.
2. Identify improvements (caching, smaller base images, security).
3. Apply a patch with clear comments.
4. Document changes in the commit message or relevant `.md` file.

**Example prompt:**
> Optimize the `Dockerfile` to cache dependencies and reduce layer count.

---

### 4. Bug Fix / Debugging
**When:** Fixing a broken feature or unexpected behavior.

**Steps:**
1. Reproduce the issue (review error logs, code flow).
2. Identify root cause.
3. Apply a minimal patch.
4. Add a regression test if applicable.

**Example prompt:**
> Fix the issue in `crew_agents.py` where API calls timeout on large datasets.

---

### 5. Documentation Update
**When:** Clarifying setup, adding examples, or updating guides.

**Steps:**
1. Read the existing doc.
2. Identify gaps or unclear sections.
3. Apply a patch or create a new `.md` file.

**Example prompt:**
> Update `AWS_DEPLOYMENT_GUIDE.md` with troubleshooting steps for Lambda cold starts.

---

## Workflow: Patch → Test → Finalize

1. **Patch:** Apply focused code changes using `apply_patch` or edits.
2. **Test:** Run local tests (`pytest`, manual checks) to validate.
3. **Finalize:** Confirm changes work, then offer next steps or commit guidance.

---

## Tool Preferences

- **For edits:** Use `apply_patch` for clarity and auditability.
- **For exploration:** Use `file_search`, `grep_search` for quick code inspection.
- **For tests:** Use `run_in_terminal` to run `pytest` locally.
- **For multi-step work:** Use `manage_todo_list` to track progress.

---

## Linting & Style

- **Format:** Follow `black` (line length 88).
- **Imports:** Use `isort` for consistent ordering.
- **Type hints:** Add where practical (especially function signatures).
- **Docstrings:** Use triple quotes; explain purpose and key parameters.

---

## When to Ask for Clarification

- Ambiguous requirements (e.g., "fix performance" — on which metric?).
- Large scope changes (e.g., refactoring >500 lines or adding a new module).
- Infrastructure or deployment decisions (e.g., changing AWS configs).

---

## Quick Reference

| Task | Typical Command / Approach |
|------|----------------------------|
| View file | `read_file` or open in editor |
